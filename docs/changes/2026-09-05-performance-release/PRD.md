# Agent Pulse 1.0 性能与可靠性

## 目标

长时间运行时，CPU、内存和磁盘工作量应主要取决于新数据和受影响统计范围；保证实时状态、拖动交互与历史统计正确。完成优化、PR 审查及合并，安装应用并重新打开，发布 GitHub 1.0.0，此后 main 更新自动按 Semantic Versioning 发布。

## 验收要求

1. 文件扫描不得因固定整文件预算永久跳过大文件；追加读取可恢复，截断、替换、半行、累计用量与工具关联正确。文件 checkpoint 和统计状态原子提交，不持久化会话正文。
2. 实时每行 JSON 只解码一次供各提取器复用；Claude Desktop 状态增量处理；模型逆向查找每行最多检查一次；过期运行态事件释放，静态历史摘要避免每秒全量重建。
3. 有效状态变化及时发布，禁止以防抖、节流或降频获得通过结果。目录清单和必要元数据复用，checkpoint 批量查询。
4. 增量作用域以 logical 组与持久 bucket 映射为基础；所有扩张过程有上界及收敛判定，未收敛回退全量。全量参考结果不可改变。
5. 小增量不再加载全部旧 bucket/session/edit 对象；计数、映射与 skill 归属优化必须用真实查询及全量等价性验证。
6. 账本后台执行不人为限制磁盘吞吐；重叠索引和临时表优化验证读写总成本。不以删除历史、备份或开启有损冻结压实作为无损优化。
7. 总曲线只计算一次，主线程仅发布结果；发布使用新载荷，快照只按真实显示输入判断变化。悬浮球、菜单及看板外观不发生非必要变化。
8. 恢复失败可以重试；上报配置失效不关闭本地采集；交互路径不等待繁重账本队列；SQLite 错误不能冒充 DONE 或空状态。
9. CPA 处理同毫秒、晚到、接口身份迁移、分页失败恢复；网络分页内存有界且不阻塞本地统计。上报继续满足精确 ACK、revision、凭证保密和未知发送结果处理。
10. 验证实际行为而非源码关键词或 SQL 副本。严格性能检查不得静默 SKIP；测量固定合成负载的 CPU/墙钟、内存及数据库/WAL/临时空间，禁止生产库重扫描。
11. GitHub PR 执行自动验证；独立审查、必要 UI 视觉验证通过后合并，不跳过失败检查。
12. 首个正式版本为 v1.0.0，release 有 macOS arm64 App 压缩包和 checksum，bundle 版本与 tag、构建 SHA 一致。
13. 后续 main 新提交自动发布；breaking change 递增 major，feat 递增 minor，其余递增 patch。按 first-parent 未发布提交顺序推进，通常一次 squash push 对应一版；连续 push 不漏末端版本，重试幂等，不创建递归版本提交。
14. 安装已验证版本到 /Applications/AgentPulse.app，退出旧实例并重新打开，确认进程路径、版本、签名和可见 UI。

## UI 验证场景

### 已安装应用显示并响应交互

WHEN 重新打开已安装应用，拖动悬浮球并打开任务气泡、TPS 看板和设置。

THEN 悬浮球跟随拖动，菜单/气泡/曲线可见，窗口响应输入，应用仍在运行。

### 刷新与显示保持一致

WHEN 可见界面的采样和统计状态更新，切换趋势颜色或显示设置。

THEN 真实变化立即进入相应视图，无旧值延迟、空白曲线或无关布局跳变。

## 完成证据

测试命令及退出码、固定 fixture 的资源记录、独立审查结果、UI 操作证据、PR/合并 SHA、release URL/tag/assets、Actions 自动发布记录、安装进程与 bundle 信息。尚未测量的长期行为不得以短采样替代证明。
